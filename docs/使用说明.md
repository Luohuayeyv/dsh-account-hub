# dsh-account-hub 中文使用说明与注意事项

> 适用版本：dsh-account-hub 0.1.0 · DeepSeek Harness（桌面版 / dsh web profile）
> 插件仓库：https://github.com/Luohuayeyv/dsh-account-hub

## 一、这个插件能做什么

- 在 DeepSeek Harness 的 **设置 → 账号管理** 中保存网站账号（网址 + 账号 + 密码，可选登录页、搜索地址模板、备注、登录方式）。
- 把账号登录会话交给 **子智能体** 使用：子智能体可以「带着你的登录态」去搜索、打开并阅读需要登录/付费墙的页面（例如期刊站点、内部资料库、社交平台）。
- 遇到 **验证码 / 人机验证 / 短信或 TOTP 二次验证 / 通行密钥（passkey）** 时，自动打开**可见的 Edge 浏览器窗口**，由你亲手完成验证；插件只负责等待与检测，**不会自动破解验证码**。
- 密码在**本机加密**保存，任何界面、接口、工具结果、日志都不会返回明文密码。

## 二、安装

在 DSH 里打开 **插件 → 添加插件**，弹窗提示「输入插件的包名、GitHub 仓库地址或本地目录路径」，把下面任意一种填进去：

| 方式 | 填写内容 | 说明 |
|---|---|---|
| **GitHub 仓库地址（推荐）** | `https://github.com/Luohuayeyv/dsh-account-hub` | 需要本机已安装 git（DSH 会先用 `git ls-remote` 检查仓库） |
| **GitHub 源（固定版本，需 git）** | `github:Luohuayeyv/dsh-account-hub#v0.1.0` | 固定到 v0.1.0 |
| **本地 tgz（无需 git）** | `dsh-account-hub-0.1.0.tgz` 的**绝对路径** | 从 [Releases v0.1.0](https://github.com/Luohuayeyv/dsh-account-hub/releases/tag/v0.1.0) 下载 |
| **本地克隆目录** | 克隆目录的**绝对路径** | `git clone https://github.com/Luohuayeyv/dsh-account-hub.git` 后使用 |

> 注意：不要只填 `dsh-account-hub` 或 `dsh-account-hub.git` 这类片段（本插件未发布到 npm，且 `.git` 后缀不是仓库地址）；请填**完整的 GitHub 地址**、**完整的本地绝对路径**或上表中的 spec。如果提示「未找到相关插件」，请检查是否填了完整地址/路径。

安装完成后**刷新 Harness 页面**，左下角 **设置 → 账号管理** 即会出现。本机需要安装 **Microsoft Edge**（也支持 Chrome；可在插件配置项 `browserPath` 指定浏览器路径）。

卸载：`plugin_manager` → `remove_bundle`，target 填 `dsh-account-hub`。账号数据目录 `%USERPROFILE%\.dsh\account-hub\` 可手动删除。

## 三、设置页使用

### 1. 添加账号

| 字段 | 说明 |
|---|---|
| 名称（可选） | 显示用名称，例如「Nature」「GitHub」 |
| 网站地址（必填） | 站点入口，如 `https://www.nature.com` |
| 登录页地址（可选） | 登录入口是独立页面时填写，如 `https://github.com/login`；留空则使用网站地址 |
| 账号（必填） | 站点登录账号 |
| 密码（必填*） | 本机 AES-256-GCM 加密保存；**手动登录模式下可留空** |
| 搜索地址模板（可选） | 如 `https://www.nature.com/search?q={query}`，`{query}` 会替换为检索词；留空时插件会猜测站点 `/search?q=` |
| 备注（可选） | 任意说明 |
| 登录方式 | **自动填写账号密码**（默认）/ **手动登录（Google / Apple / 通行密钥 / 验证码等）** |
| 搜索时显示浏览器窗口 | 勾选后每次抓取都弹出可见窗口（个别网站检测无头浏览器时使用） |

### 2. 登录并验证

- 自动填表模式：点「登录并验证」后，插件打开可见 Edge 窗口，自动填写账号密码并提交；成功后自动保存会话并关闭窗口。
- 手动登录模式：点「打开登录窗口」后，插件**只打开窗口、不填表**；你在窗口里用密码 / Google / Apple / 通行密钥 / 短信验证码等任意方式完成登录，然后回到设置页点「我已完成验证」（插件通常也会自动检测到成功）。
- 遇到验证码 / 人机验证 / 二次验证：窗口会一直保留，完成后点「我已完成验证」；成功后会话保存，子智能体可直接使用。
- 「测试会话」：快速检查当前登录是否有效（返回页面标题 / 文本片段）。

### 3. 账号状态

- **已登录**：会话有效。
- **未登录 / 已过期**：点一次「登录并验证」或「打开登录窗口」重新登录。
- **需要真人验证**：在打开的窗口中完成验证，然后点「我已完成验证」。
- **登录失败**：查看卡片上的错误信息；可点「编辑」同步最新密码或切换登录方式。

## 四、子智能体如何使用

插件向主 Agent 与所有子智能体注册 4 个工具（无需额外配置）：

| 工具 | 作用 |
|---|---|
| `account_hub_list` | 列出已保存账号与登录状态（不含密码） |
| `account_hub_search` | 用指定账号登录会话在站点内搜索：`{account, query}` |
| `account_hub_fetch` | 用登录会话打开任意 URL 并读取正文/链接：`{account, url}` |
| `account_hub_login` | 打开可见登录窗口（立即返回，不等待用户） |

`account` 参数可传账号 id（`acc_...`）或账号名称（不区分大小写，重名时用 id）。

**使用示例（直接对 Agent 说）**：
- 「用 Nature 账号检索 'quantum computing' 最新综述并总结前 3 篇」
- 「用 GitHub 账号读取我的私有仓库 README」
- 「用 XX 账号打开这个链接并总结正文内容：https://...」

Agent 返回 `verification-required` 或 `login-required` 时：按提示告诉用户「请在打开的浏览器窗口完成登录/验证」，用户完成后重新调用同一工具即可。

## 五、数据与安全

- 数据目录：`%USERPROFILE%\.dsh\account-hub\`
  - `accounts.json`：账号数据（密码字段 AES-256-GCM 加密）
  - `secret.key`：本机加密密钥（32 随机字节）
  - `profiles/<账号 id>/`：每个账号独立的浏览器 profile（含该站点登录 cookie）
- **删除账号** = 取消进行中的浏览器操作 + 删除该账号的浏览器 profile（含 cookie）+ 删除账号记录。
- 本地 HTTP 接口仅监听本机 Harness 端口（如 `127.0.0.1:50461`），按本机单用户威胁模型设计：接口永远不返回明文密码；请勿把该端口暴露到公网。
- 插件不会读取或修改你在其他浏览器（如日常 Edge/Chrome）中的登录数据；每个账号的会话都保存在插件自己的 profile 中。

## 六、注意事项（重要）

1. **不自动破解验证码**：验证码 / 人机验证 / 二次验证 / passkey 必须由真人完成，这是有意的安全设计，也符合网站条款。
2. **第三方登录需要网络可达**：`Continue with Google` / `Continue with Apple` 等需要浏览器能访问 accounts.google.com / appleid.apple.com。如果插件浏览器打不开第三方站点（例如网络/代理限制），请改用该网站的密码或 passkey 登录，或者把登录方式设为「手动登录」。
3. **自动填表有边界**：只覆盖常见标准登录表单。多步登录、iframe / Shadow DOM 登录框、passkey-only 账号、需要图形验证码的账号，请在弹窗中手动完成。
4. **无头浏览器检测**：个别网站会检测无头模式导致抓取失败；在该账号「编辑」里勾选「搜索时显示浏览器窗口」后重试。
5. **会话会过期**：登录会话保存在本机浏览器 profile 中（持久 cookie 约 7 天，具体以站点为准）；站点会话过期后需要重新点一次登录。
6. **同一账号串行**：同一账号同时只允许一个浏览器操作；正在登录/验证时，新的抓取请求会返回忙碌或等待状态。
7. **修改密码要同步**：站点密码修改后，请在账号「编辑」里更新密码；「手动登录」模式不依赖保存的密码（可留空）。
8. **网络与代理**：插件使用本机系统网络。若需代理才能访问目标站点，请确保系统代理/VPN 对 Edge 生效；否则可能表现为连接超时或 `ERR_CONNECTION_CLOSED`。
9. **合规使用**：请确认目标网站的服务条款允许自动化访问，且你只访问自己有权访问的内容；不要用于爬取受版权保护的内容或绕过付费限制。
10. **浏览器要求**：需要本机安装 Microsoft Edge 或 Chrome；首次登录可能较慢（浏览器冷启动）。
11. **数据备份**：`accounts.json` 与 `secret.key` 需一起备份；只备份其中一个会导致密码无法解密。更换电脑时账号需要重新登录（浏览器 profile 与 cookie 不跨机器迁移）。
12. **Harness 兼容性**：插件依赖 Harness 的 Tool / Slot / WebServer 接口；升级 Harness 大版本后如设置页或工具不可用，请更新插件到最新版本。

## 七、常见问题（FAQ）

**Q1：点登录后没看到浏览器窗口？**
窗口可能被其他窗口遮挡或在任务栏中（标题类似 `github.com - 个人 - Microsoft Edge`），请在任务栏找 Edge 图标并打开。若确实没有窗口，查看设置页错误提示，或先关闭其他 Edge 窗口后重试（同一 profile 已被占用时启动会失败）。

**Q2：提示「已打开浏览器窗口（不会自动填写账号密码）」？**
说明该账号是「手动登录」模式。请在窗口里手动完成登录（可用 Google/passkey/验证码），然后点「我已完成验证」。

**Q3：Google 登录页打不开 / `ERR_CONNECTION_CLOSED`？**
插件浏览器没有走到你的代理；请为该网络开启系统代理/VPN，或改用网站密码/passkey 登录，或切换为「手动登录」。

**Q4：抓取返回 `verification-required` / `login-required`？**
说明会话失效或站点要求验证：按提示在打开的窗口中完成登录/验证后重试。

**Q5：抓取内容为空或只有登录框？**
可能被无头检测或需要 JS 渲染：勾选「搜索时显示浏览器窗口」重试；或先用「测试会话」确认登录有效。

**Q6：删除账号后 cookie 还在吗？**
不在。删除账号会删除对应的浏览器 profile 目录（含登录 cookie）。

**Q7：账号数据在哪？如何彻底清除？**
在 `%USERPROFILE%\.dsh\account-hub\`；关闭 Harness 后删除整个目录即可（会丢失所有已保存账号）。
